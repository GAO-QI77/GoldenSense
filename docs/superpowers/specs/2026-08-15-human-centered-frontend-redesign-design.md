# GoldenSense 人本化前端整体体验重构设计

## 1. 目标与边界

本轮把 GoldenSense 从“面向评委和量化研究员的功能终端”调整为“小白可理解、专业用户可审计”的黄金研究产品。保留现有黑金视觉、四条主路由、ResearchCase 闭环和简明/专业模式，不进行品牌推倒重做。

成功标准：用户进入首页 5 秒内能确认市场时点、黄金状态、主要驱动和信息是否新鲜；普通用户无需理解模型缩写即可完成研究；专业用户仍能展开证据、模型、口径和审计链。

## 2. 信息架构

### 首页：先市场，后研究

首页按以下顺序排列：

1. **市场快照**：XAUUSD 价格与日变化、数据时间、实时/延迟状态、美元指数、10 年实际利率、波动状态、ETF/资金流状态。任何缺失项单独标记，不用 `N/A` 冒充正常。
2. **一手信息流**：优先展示央行、统计机构、财政部、交易所、CFTC、World Gold Council 等原始发布；每条显示来源等级、发布时间、与黄金的关联、是否已被市场消化。转载和二手解读默认折叠到“补充背景”。
3. **今日研究摘要**：用普通语言回答“发生了什么、为什么影响黄金、最大反方因素、下次复核时间”。
4. **统一研究案件入口**：URL、PDF、图片和研究问题进入 Evidence Shield 与多 Agent 闭环。
5. **深度指标与历史背景**：趋势、三期限情景、指标支柱、数据质量和来源审计。简明模式折叠方法，专业模式展开。

首页任何核心接口失败时，相关区域进入统一的 `unavailable` 状态。历史观点可以继续展示，但必须明确标为“历史研究参考”，不得同时出现“接口异常”“当前可用”“质量正常”。

### 量化研究页

保留旗舰策略、HMM、情景锥、公允价值、宏观因子、波动分布和校准面板。简明模式先展示结论、可靠性和失效条件；模型名称、参数、公式和样本外指标进入专业展开层。

展示前增加数值可信度规则：

- 半衰期超出可解释上限、非有限值或回归关系无效时，显示“未观察到有效均值回归”，不展示夸张天数。
- 公允价值偏离必须同时解释 z 分、结构断点和模型适用性，不能只用“正常”概括。
- 校准记录按稳定标识去重；完全相同的记录不重复占据列表。
- 无法评分的安全弃权不显示为 0 分或优秀结果。

### 观点书与台账页

首屏保留短、中、长期观点和数据时点。简明模式使用普通语言，专业模式再显示模型代号、证据链、哈希和评分方法。空台账提供明确下一步：“发布首个研究案件后开始前向记录”。

### 个性化投研页

采用三步流程：

1. 基础画像：风险承受力、期限、经验、当前黄金占比。
2. 适当性信息：损失承受力、回撤、应急资金、负债、工具、法域和基础货币。
3. 研究结果：适当性结论、参考区间、个人差距、三期限关注点、失效条件和复核时间。

画像未完成时显示完成进度和缺失项目，不计算或展示“画像风险 Score”。只有适当性数据达到规则要求后才展示风险等级。期货、期权、CFD和中高杠杆继续触发限制，不输出个人仓位差距。

桌面端可以在一页内使用分区步骤；手机端一次只显示一个步骤，并提供固定底部“上一步/下一步/生成研究”操作区。

## 3. 简明与专业模式

### 简明模式

- 只使用“当前结论、原因、风险、复核时间、数据状态”五类核心信息。
- 首次出现专业词时提供中文解释，不直接暴露 HMM、HAR-RV、BL-lite、Brier、OOS 等缩写。
- 场景使用“上行情景/基准情景/下行情景”，避免“降低暴露、分批观察”等操作性语言。
- 风险、陈旧、不可用和安全弃权永远不可隐藏。

### 专业模式

- 展示模型名称、样本期、样本外指标、参数口径、概率类型、Agent 分歧和完整引用。
- 保留当前审计能力，但使用一致的中文字段名，并提供术语说明。

## 4. 状态与错误模型

建立共享的前端展示状态：`loading | current | delayed | degraded | unavailable`。

- `loading`：使用骨架屏并设置 `aria-busy`。
- `current`：只有数据存在、未陈旧且核心链路成功时使用。
- `delayed`：显示具体数据时间与延迟属性。
- `degraded`：展示仍可用的部分和降级原因。
- `unavailable`：隐藏派生结论，展示普通语言错误、影响范围和“重新加载”按钮。

错误信息不得直接暴露 `RuntimeError`、`ConnectError` 或内部服务名。技术详情只允许出现在专业审计展开区。

## 5. 移动端与无障碍

- 760px 以下使用紧凑顶部栏：品牌、简明/专业切换、搜索。
- 四个主页面改为固定底部导航；页面增加安全底部留白。
- 所有主要触控目标最小 44×44px，输入字号不低于 16px。
- 搜索弹窗实现焦点锁定、Esc 关闭和关闭后焦点回到触发按钮；列表项补充标准 ARIA 状态。
- 错误、加载和完成状态使用 `role=alert/status` 或 `aria-live` 播报。
- 所有动画保留 `prefers-reduced-motion` 回退。

## 6. 组件与数据边界

新增或整理以下前端边界：

- `MarketSnapshotHero`：只展示经过统一状态判断的市场快照。
- `PrimarySourceFeed`：区分一手来源和补充背景，支持新鲜度与来源标签。
- `ResearchSummary`：从结构化数据生成简明五要素，不重新计算模型数字。
- `DataStateBoundary`：统一 loading/degraded/unavailable 展示与重试。
- `ProfileStepper`：管理画像步骤、完成度和移动端固定操作区。
- `modelPresentation`：半衰期、评分、概率口径和异常值的纯展示规则。

后端仍是数字和治理状态的权威来源；前端只做状态组合、合理性展示和渐进披露。若后端给出明显不可解释的数字，前端应安全降级，同时保留专业模式审计入口。

## 7. 测试与验收

所有行为先通过失败测试固定，再写生产代码。

- 首页接口失败时不得出现“当前可用”“质量正常”或实时派生结论。
- 首页首屏顺序必须是市场快照、一手信息流、今日摘要，再到研究案件入口。
- 一手信息显示官方来源、新鲜度和发布时间；二手内容不能伪装成一手来源。
- 未完成画像不得显示风险分；补全且通过适当性后才展示风险等级。
- 手机端顶部导航不再纵向占满首屏，主导航触控高度不低于44px。
- 手机端个性化流程分步完成，主要操作始终可见。
- 异常半衰期显示安全解释，重复校准记录只展示一次。
- 简明模式不出现未解释的核心模型缩写和操作性投资文案。
- 错误提示可恢复、可被屏幕阅读器播报，搜索弹窗焦点可正确进出。
- 最终运行完整 Python 测试、前端生产构建、桌面与移动端 Playwright，并通过真实本地网关浏览器验收。

## 8. 不在本轮范围

- 不更换黑金品牌、主字体或四条主路由。
- 不引入新的交易执行或下单能力。
- 不承诺把所有行情升级为交易所级实时数据；数据等级与延迟必须诚实展示。
- 不增加与当前黄金研究主任务无关的社交、社区或复杂账户系统。
