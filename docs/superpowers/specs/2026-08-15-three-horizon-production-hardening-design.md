# GoldenSense 三周期与生产强化设计

## 目标

将 GoldenSense 的公开研究周期统一为短期、中期、长期，并修复真实连通测试暴露的行情一致性、限流、安全措辞、证据可用性、台账可信度和移动端交互问题。最终评分必须依据可重复测试，不以功能数量或主观观感代替证据。

## 公开周期合同

- `short_term`：短期，覆盖 1–21 天。
- `mid_term`：中期，覆盖 1–6 个月。
- `long_term`：长期，覆盖 6 个月以上。
- 前端、公开 API、ResearchCase、AgentView、策略、个性化和台账只使用上述三种公开键。
- 原有 `24h/7d/30d` 和 `T+1/T+7/T+30` 仅允许存在于内部模型兼容层和旧记录迁移器中，且必须带 `legacy` 命名，不得重新泄漏到公开响应。

## 行情可信链

读取首页只读取已验证快照，不触发第三方刷新。刷新由后台任务或内部接口执行，并由单飞锁保证同一时刻只运行一次。每个标的必须同时校验请求 ticker、返回 symbol、价格范围、时间和字段身份；黄金价格异常跳变或疑似串标时，不覆盖最后可信快照，并输出 `degraded` 或 `blocked`。

`GC=F` 必须标注为 COMEX 黄金期货，不能显示为 XAUUSD。只有现货数据提供商返回的黄金现货才可使用 XAUUSD 标签。量化研究中的历史期货、公允价值锚和实时快照必须展示各自口径与时点。

## 限流与降级

普通 GET、分析生成、研究案件创建、文件上传和个性化使用独立限流桶。普通页面切换不能耗尽分析额度。429 响应包含中文信息、`Retry-After` 和结构化重试秒数。前端将其展示为可恢复状态，不显示英文后端异常。

## 投资安全与证据门控

旧分析接口与 ResearchCase 共用输出政策。禁止目标仓位、买入、卖出、加仓、减仓、满仓、杠杆倍数等直接指令；允许教育型参考区间、当前暴露与参考区间的差距、风险情景和复核条件。

提示注入即使被成功忽略，也必须在降级标记或门控报告中可见。Evidence Shield 的重复检测按事实聚类降级，不因标题或章节重复把整份正常文档全部拒绝。非市场材料由产品规则审查角色处理，不强行生成黄金方向。

## 信息源与台账

首页优先展示央行、美联储、CFTC、CME、WGC 等原始来源，媒体内容只能进入补充背景。没有一手信息时必须明确显示缺口。

台账区分历史回测、模拟前向和真实前向。空台账不伪造历史成绩，但提供首次发布的条件说明。健康检查继续把缺失周度发布视为运营告警。

## 前端体验

保留黑金研究终端视觉体系。首页顺序保持市场快照、一手信息、研究摘要、统一研究案件。桌面与移动端所有主要交互目标至少 44px；降级和限流信息统一中文化并给出恢复动作。

## 客观评分规则

总分 100：数据可信度 25、研究闭环 20、Agent 与模型治理 15、安全合规 15、产品体验 15、运维测试 10。

评分超过 90 的硬门包括：

1. 100 次并发行情读取只返回同一个可信黄金价格。
2. 公开 API 和前端不出现旧周期名称。
3. 提示注入、单位攻击和串标数据被可视化降级或阻断。
4. 所有公开输出不含目标仓位或直接交易指令。
5. 四页面真实连通，正常切页不触发限流。
6. Python 测试、前端单测、构建和真实 Playwright 全部通过。
7. 台账明确标注成绩属于回测、模拟前向还是真实前向。

若任一硬门未通过，最终评分不得超过 89。
